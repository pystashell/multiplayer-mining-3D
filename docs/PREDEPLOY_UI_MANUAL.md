# 发布前 UI 人工测试手册

> 本文件由 `config/predeploy-ui-checklist.json` 自动生成。
> 请不要直接编辑；修改清单后运行 `npm run ui:manual`。

## 适用范围

这份手册负责自动化源码测试无法证明的视觉与真实交互结果，包括遮挡、裁切、人物一致性、触摸手感、双浏览器同步和控制台清洁度。

自动化测试通过不等于 UI 验收通过。任何正式部署都必须同时具备：

1. `npm test` 通过。
2. `npm run deploy:dry` 通过。
3. 本手册全部场景通过并留下证据。
4. `npm run ui:check` 确认验收记录仍绑定当前源码。

## 执行与记录

1. 运行 `npm run dev`，打开终端显示的本地地址。
2. 按下列场景逐项执行；发现失败立即停止，不得勾选通过。
3. 截图建议放在仓库外或团队约定的证据目录，避免把临时截图混入产品资源。
4. 全部通过后执行：

```powershell
npm run ui:approve -- --reviewer "验收人" --browser "Chrome 版本/系统" --evidence "截图目录或证据链接" --confirm-all
```

5. 把生成的 `predeploy/ui-approvals/vX.Y.Z.json` 与待发布代码一起提交。
6. 任何 `public/` 文件或本清单变化都会改变摘要，使旧验收自动失效。

## 失败判定原则

- 产品行为错误：修复产品代码，然后从自动化测试重新开始。
- 需求明确改变：先更新需求、清单和实现，再重新完成全部受影响场景。
- 仅测试步骤过时：必须证明用户可见行为仍正确，再更新清单；不能直接跳过。
- 浏览器或网络偶发问题：保存证据并复现；无法解释的失败仍然阻止发布。

## 1. 桌面大厅与中英文切换

**目的：** 确认大厅结构、当前配置角色的显示文本和双语切换在桌面端可读。

**测试环境：** 桌面宽屏（1440 × 900，鼠标 + 键盘）；桌面紧凑窗口（1280 × 720，鼠标 + 键盘）

**步骤：**

1. 打开本地首页并清空旧会话状态。
2. 分别切换中文和英文，检查标题、任务说明、按钮、角色姓名、代号与职业。
3. 缩放窗口到两个指定桌面尺寸并滚动大厅。

**通过标准：**

- 角色显示值与 public/guide-character.js 当前配置一致，没有未解析模板标记。
- 中英文没有混排、截断、重叠或不可达按钮。
- 大厅在紧凑高度下仍可滚动，主要操作始终可用。

**证据：** 每种语言至少一张完整大厅截图。

**失败处理：** 检查角色模板、翻译键、容器高度和溢出样式；修复后重跑自动化并重新执行本场景。

## 2. 全故事路线的引导角色一致性

**目的：** 确认所有剧情与任务插图都使用同一个当前配置角色，不混入旧角色或其他人物设计。

**测试环境：** 桌面宽屏（1440 × 900，鼠标 + 键盘）

**步骤：**

1. 依次进入初级、中级、高级、终极与多人任务入口。
2. 触发每条路线可见的主插图和对话插图。
3. 逐张比较脸型、发型、服装、配色和身份文本。

**通过标准：**

- 所有人物图都与当前配置角色保持一致，仅允许场景、动作和构图变化。
- 没有旧角色、旧作品标志、旧阵营词或错误姓名。
- 图片比例和裁切适合对应卡片或对话框。

**证据：** 按路线保存截图，文件名包含路线和画面位置。

**失败处理：** 回到 GUIDE_ART 映射和实际素材核对；替换错误资源后重新验收全部路线，不能只看单张。

## 3. 桌面对话框与插图可读性

**目的：** 确认插图不会遮挡对白、按钮和关闭提示，长文本仍能阅读。

**测试环境：** 桌面宽屏（1440 × 900，鼠标 + 键盘）；桌面紧凑窗口（1280 × 720，鼠标 + 键盘）

**步骤：**

1. 触发包含主图、提示图和较长文本的多段对话。
2. 使用鼠标继续、关闭并重新打开对话。
3. 在紧凑窗口检查滚动、焦点和背景遮罩。

**通过标准：**

- 文字、人物主体与按钮均不被裁切或互相覆盖。
- 点击插图或游戏区域不会误触跳过两段内容。
- 关闭后输入焦点和游戏操作恢复正常。

**证据：** 至少保存一张长文本和一张带人物插图的对话截图。

**失败处理：** 检查对话 DOM 层级、object-position、overflow、兼容点击抑制和焦点恢复。

## 4. 桌面棋盘、HUD 与相机操作

**目的：** 确认桌面端的挖掘、插旗、双键、旋转、平移、缩放、切片和返回大厅可实际操作。

**测试环境：** 桌面宽屏（1440 × 900，鼠标 + 键盘）；桌面紧凑窗口（1280 × 720，鼠标 + 键盘）

**步骤：**

1. 开始单人任务，分别执行挖掘、插旗、双键自动揭示和提示操作。
2. 执行相机旋转、平移、缩放、锁定中心、重置视角和切片。
3. 打开设置、通讯和返回大厅控件。

**通过标准：**

- 点击目标与高亮格一致，不会因镜头角度误选其他格。
- HUD、推理面板和教程提示不遮挡关键棋盘区域。
- 所有常用控件可见、可点击且状态反馈明确。

**证据：** 保存默认视角与紧凑窗口各一张游戏截图，并记录完成的操作列表。

**失败处理：** 根据问题检查命中测试、相机手势、布局层级和响应式 CSS；修复后复测全部桌面操作。

## 5. 手机大厅与剧情对话

**目的：** 确认手机竖屏上的大厅、角色图、语言切换和对话操作不溢出。

**测试环境：** 手机竖屏（390 × 844，触摸）；小屏手机（360 × 640，触摸）

**步骤：**

1. 以触摸设备模式打开首页，分别检查两个手机尺寸。
2. 切换语言、选择任务并进入第一段对话。
3. 滚动长内容并完成对话。

**通过标准：**

- 页面没有水平滚动、双重滚动锁死或屏幕外按钮。
- 角色主体裁切合理，文本与人物图不互相遮挡。
- 单次触摸只触发一次动作。

**证据：** 两个尺寸各保存大厅和对话截图。

**失败处理：** 检查移动端媒体查询、安全区、触摸兼容点击和滚动容器；修复后两个尺寸都要重测。

## 6. 手机棋盘与触摸控制

**目的：** 确认触摸长按、移动操作区、抽屉、提示和安全区在小屏上可用。

**测试环境：** 手机竖屏（390 × 844，触摸）；小屏手机（360 × 640，触摸）

**步骤：**

1. 进入单人棋盘，执行点击挖掘、长按插旗、长按后移动平移和双指操作。
2. 逐个使用五键操作区、推理提示、退出推理、切片和控制抽屉。
3. 旋转设备后再返回竖屏，继续一次棋盘操作。

**通过标准：**

- 长按插旗与长按平移不会串动作，取消手势后不会卡住。
- 底部安全区、提示、抽屉和棋盘之间没有不可操作的重叠。
- 旋转后布局恢复且当前游戏状态不丢失。

**证据：** 至少保存一张操作区完整截图，并记录长按与旋转结果。

**失败处理：** 检查输入模式、pointer cancel、移动端层级与安全区计算；修复后从进入棋盘开始重测。

## 7. 双客户端多人同步

**目的：** 确认两个真实浏览器客户端的大厅邀请、角色故事、行动同步和离开流程一致。

**测试环境：** 桌面宽屏（1440 × 900，鼠标 + 键盘）；手机竖屏（390 × 844，触摸）

**步骤：**

1. 桌面客户端创建房间，手机尺寸客户端通过邀请链接加入。
2. 两端轮流挖掘、插旗，观察昵称、活动、棋盘和任务状态。
3. 分别测试一端刷新重连、主动离开和房主转移。

**通过标准：**

- 两端公开状态一致，操作不会重复执行或丢失。
- 中英文客户端可各自本地化相同活动。
- 刷新与离开后没有幽灵成员、重复连接或错误房间 URL。

**证据：** 保存同一房间的双客户端截图并记录房间码与测试时间；不要记录密钥。

**失败处理：** 停止发布，检查 WebSocket、ACK/序号、恢复快照、离开协议和 Durable Object 日志。

## 8. 失败、撤回、成功与回放恢复

**目的：** 确认关键任务生命周期在视觉和交互上完整，不会把失败状态带入下一局。

**测试环境：** 桌面宽屏（1440 × 900，鼠标 + 键盘）；手机竖屏（390 × 844，触摸）

**步骤：**

1. 在单人任务触发失败，执行撤回或重新开始。
2. 完成一局并进入成功回放，测试暂停、继续和退出。
3. 回到大厅后再次开始任务。

**通过标准：**

- 失败、撤回、成功和回放都有清晰且互不冲突的视觉反馈。
- 回放期间普通输入被锁定，退出后恢复最新权威状态。
- 新任务没有残留弹窗、提示、音频或旧棋盘状态。

**证据：** 记录失败画面、回放 HUD 和重新进入后的画面。

**失败处理：** 检查任务状态清理、回放缓冲、动画队列、音频会话和大厅返回逻辑。

## 9. 键盘焦点与基本可访问性

**目的：** 确认不用鼠标也能遍历主要 HTML 控件，焦点可见且对话语义完整。

**测试环境：** 桌面宽屏（1440 × 900，鼠标 + 键盘）

**步骤：**

1. 从页面顶部开始只使用 Tab、Shift+Tab、Enter、Space 和 Escape。
2. 遍历语言、任务、设置、对话关闭、回放和返回大厅控件。
3. 检查浏览器可访问性树中的按钮名称和对话语义。

**通过标准：**

- 焦点顺序与画面顺序一致，焦点样式清晰。
- 主要控件有可理解名称，不存在键盘陷阱。
- 对话打开时焦点不会落到被遮挡的后台控件。

**证据：** 记录浏览器、完成的键盘路径和发现的问题；可附可访问性树截图。

**失败处理：** 检查语义元素、tabindex、aria 属性、焦点圈和对话焦点管理。

## 10. 控制台、资源与网络清洁度

**目的：** 确认正常流程没有脚本异常、资源 404、外部运行时依赖或敏感信息泄露。

**测试环境：** 桌面宽屏（1440 × 900，鼠标 + 键盘）；手机竖屏（390 × 844，触摸）

**步骤：**

1. 清空浏览器控制台和网络面板后完整走一遍大厅、任务、对话和返回大厅。
2. 过滤 failed、404、CORS、WebSocket 和未捕获异常。
3. 检查字体、脚本、图片和音频均来自预期本地或同源路径。

**通过标准：**

- 没有未解释的控制台错误、资源失败或持续重连。
- 没有依赖未批准的第三方运行时 CDN。
- URL、日志和响应中不出现密钥、令牌或服务端私有雷区。

**证据：** 保存控制台与失败请求过滤后的截图；若有已知无害警告，必须在验收备注解释。

**失败处理：** 任何未知异常或资源失败都阻止发布；定位资源映射、缓存、CSP、安全头或网络协议后重新执行完整场景。
